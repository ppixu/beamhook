## The problem

Open a YouTube video and macOS quietly hands your media keys to Safari. Apple
Music grabs them the moment it launches. You press play expecting Spotify and
pause a video three tabs away — and the only reliable fix is to restart
something. macOS has no built-in setting to pin the media keys to one app.

Beamhook is that setting. You pick the target; it answers every press. Nothing
else gets a look in.

## Features

- **You pick the target** — choose the single app the keys control, from the menu
  bar. It never changes on its own: no smart-switching to second-guess.
- **Nothing else can steal them** — Beamhook intercepts the key at the system
  level and swallows it, so Safari, YouTube and Apple Music never see the press.
- **Play/pause that reflects reality** — the in-menu button shows Pause when the
  target is playing and Play when it isn't.
- **Volume for what's playing** — a live list of apps currently making sound, each
  with a volume slider for the ones that are scriptable.
- **Extensible** — Spotify, Apple Music, VLC and VOX are built in; add any other
  app with one line of AppleScript.
- **Launch at login**, single process, no background daemons.

## Install

Beamhook builds from source with [XcodeGen](https://github.com/yonaskolb/XcodeGen).

```bash
git clone https://github.com/ppixu/beamhook
cd beamhook
brew install xcodegen   # one-time, if you don't have it
./run.sh
```

`run.sh` regenerates the Xcode project, signs the build with your Apple
Development identity (so the Accessibility grant survives rebuilds — see below),
compiles, and launches it. A hook icon appears in your menu bar.

> **Note:** the `.xcodeproj` is generated by XcodeGen and is **not** committed.
> Always run `./run.sh` (or at least `xcodegen generate`) after a `git pull`;
> building a stale project misses newly added files and shows up as a blank app
> icon or a missing-asset error at runtime.

## Usage

1. **Grant Accessibility** when prompted (System Settings → Privacy & Security →
   Accessibility). Required to capture the media keys.
2. Click the menu-bar icon and **pick your target app**.
3. **Press play.** The key goes where you pointed it.

**Add a custom app:** in the menu-bar popover, expand *Add a custom app…* and
enter a display name, the app's bundle ID, and an AppleScript play/pause command
(next/previous optional). For example:

```applescript
tell application "My Player" to playpause
```

## How it works

A single process installs a Quartz [`CGEventTap`](https://developer.apple.com/documentation/coregraphics/1454426-cgeventtapcreate)
on `NSSystemDefined` events. When a transport key (play/pause, next, previous)
arrives it **returns `nil`** — consuming the event so no other app sees it — then
drives the selected app directly via AppleScript / Scripting Bridge. Because the
key never reaches the system's "Now Playing" arbitration, the target you chose is
the only thing that responds.

The architecture is split into two layers:

- **`BeamhookKit`** — a framework with the pure, unit-tested logic (media-key
  decoding, the app model, volume scaling, the target manager).
- **`Beamhook`** — the app target: the SwiftUI `MenuBarExtra`, the event tap,
  permissions, login item, and the audio-process monitor.

## Permissions

- **Accessibility** — required to capture the media keys.
- **Automation** — a one-time per-app prompt the first time Beamhook controls each
  app.

### Why the Accessibility grant used to disappear (and why it doesn't now)

macOS binds the Accessibility grant to the app's **code-signing identity**. An
**ad-hoc** signed build (`codesign -s -`) has no stable identity, so its `cdhash`
changes on every rebuild and macOS silently drops the grant: the toggle still
shows "on", but `AXIsProcessTrusted()` returns `false`, the event tap never
starts, and the keys fall back to whatever the system wants.

`run.sh` therefore signs with your **Apple Development** identity (auto-detected
from the login keychain via `security find-identity`) using *manual* signing — no
Apple-ID login or provisioning profile needed. That produces a designated
requirement based on the bundle ID + certificate, identical across rebuilds, so a
one-time grant sticks.

If you're upgrading from an old ad-hoc build, clear the stale grant once:

```bash
tccutil reset Accessibility dev.local.Beamhook
./run.sh   # then grant Accessibility when prompted — it persists from here on
```

If `run.sh` warns it found **no signing identity**, add a free Apple ID in
Xcode → Settings → Accounts (which creates an "Apple Development" identity).

## Development

```bash
# Build (Release)
xcodegen generate
xcodebuild build -project Beamhook.xcodeproj -scheme Beamhook -configuration Release

# Run the unit tests
xcodebuild test -project Beamhook.xcodeproj -scheme BeamhookKit \
  -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO
```

### Distribution (sign + notarize)

Set `DEVELOPMENT_TEAM` and a real bundle-ID prefix in `project.yml`, keep a stable
signing identity, then:

```bash
xcodebuild -project Beamhook.xcodeproj -scheme Beamhook -configuration Release \
  -derivedDataPath build clean build
ditto -c -k --keepParent "build/Build/Products/Release/Beamhook.app" Beamhook.zip
xcrun notarytool submit Beamhook.zip --keychain-profile "Beamhook-Notary" --wait
xcrun stapler staple "build/Build/Products/Release/Beamhook.app"
```

## Customizing the icons

The shipped icons are a green rounded-rect app icon with a white hook glyph, and a
monochrome menu-bar hook. To replace them, edit the two masters and regenerate:

1. Replace `Icon/master-1024.png` (1024×1024 app icon).
2. Replace `Icon/menubar-master.png` (flat black-on-transparent menu-bar glyph;
   macOS re-tints it for light/dark).
3. Regenerate every size and refresh the project:

   ```bash
   ./Icon/make-icons.sh && xcodegen generate
   ```
