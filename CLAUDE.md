# CLAUDE.md

Guidance for Claude Code (claude.ai/code) when working in this repository.

## What this is

Beamhook is a **single-process macOS menu-bar app** (Swift, macOS 14+) that
captures the keyboard's hardware media keys and routes play/pause/next/previous
to **one app the user explicitly selects** — so Safari, YouTube and Apple Music
can't hijack them. Native apps are driven **via AppleScript**. Safari and Chrome
are the exception: `BrowserMediaController` injects JavaScript into tabs to list
and control individual media sources, so a browser target is per-tab rather than
per-app. Tabs are identified by a random per-page id, never by window/tab
position — see `sourceID` in `System/AppleScriptExecutor.swift`.

## Commands

The Xcode project is generated by **XcodeGen** from `project.yml` and is **not**
committed. Regenerate after any file add/remove or after `git pull`.

```bash
# Regenerate + build (signed) + launch — the normal dev loop.
./run.sh

# Just regenerate the project.
xcodegen generate

# Unit tests — pure logic (BeamhookKit) and the app-target seams (BeamhookTests).
xcodebuild test -project Beamhook.xcodeproj -scheme BeamhookKit \
  -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO
xcodebuild test -project Beamhook.xcodeproj -scheme Beamhook \
  -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO

# Regenerate icons after editing Icon/master-1024.png or Icon/menubar-master.png
./Icon/make-icons.sh && xcodegen generate
```

**Three build configurations.** `Debug` (dev loop, keeps `get-task-allow` so the
debugger attaches), `Release` (distribution hygiene: no injected entitlement,
secure timestamp), and `Official` — `Release` plus `OFFICIAL_BUILD`, which is the
only configuration that compiles Sparkle in. A "release" build that isn't
`Official` silently ships without the updater. Shipping is `./release.sh` then
`./scripts/sign-release.sh`; the whole procedure is in `RELEASING.md`.

**Signing matters (do not switch back to ad-hoc).** The media-key tap needs the
**Accessibility** permission, and macOS binds that grant to the app's
code-signing identity. `run.sh` signs with your **Apple Development** identity
(auto-detected via `security find-identity`) using *manual* signing, which gives
a stable designated requirement so the grant survives rebuilds. Ad-hoc signing
(`codesign -s -`) changes the cdhash every build, silently dropping the grant —
the tap then never starts and the keys fall back to the system. If the grant
gets confused, `tccutil reset Accessibility com.github.ppixu.beamhook` then
re-grant. (The bundle id is set in `project.yml`; older notes say
`dev.local.Beamhook`, which no longer matches anything.)

## Architecture

Two layers, deliberately separated so the logic is testable without the system:

- **`Sources/BeamhookKit/`** — pure, unit-tested logic, no AppKit system calls:
  - `MediaKey.swift`, `MediaKeyDecoder.swift` — decode `NSSystemDefined` subtype-8
    aux-button events into transport keys.
  - `AppDefinition.swift` — the Codable model for a controllable app (bundle ID +
    AppleScript snippets). `BuiltInApps.swift` — the shipped apps.
    `AppDefinitionStore.swift` — persists user-defined apps; `allDefinitions()` =
    `BuiltInApps.all + user-defined`, so built-ins are always fresh from code.
  - `MediaApp.swift` / `ScriptedMediaApp.swift` — run an app's scripts via an
    injected `ScriptExecuting`; `AppRegistry.swift` resolves apps by id.
  - `TargetManager.swift` — holds the selected target id and dispatches a key to it.
  - `TargetLauncher.swift` — launches the hooked app for a play/pause press it
    would otherwise swallow (launch → poll `isReady` → play), behind the
    `AppLaunching` / `Sleeping` seams. Never launches by Apple event: that send
    blocks until the app is up. `LaunchOnPlayPreference.swift` holds the
    default-ON setting rule.
  - `VolumeScale.swift` — normalizes app volume ranges (0–100 / 0–512 / 0.0–1.0) to %.
  - Protocol seams (`ScriptExecuting`, `AppPresenceChecking`, `MediaAppResolver`)
    let tests inject fakes.
- **`Sources/Beamhook/`** — the app target (system integration):
  - `BeamhookApp.swift` — SwiftUI `MenuBarExtra(.window)`; `AppState.swift` is the
    hub (owns the tap, watchdog, registry, target manager, permissions).
  - `System/MediaKeyTap.swift` — a `CGEventTap` on a dedicated thread that swallows
    the transport keys (`return nil`) and forwards them to `AppState`.
    `TapWatchdog.swift` re-enables/recreates it (timeout, sleep/wake).
  - `System/AppleScriptExecutor.swift` — also holds `BrowserKind`,
    `BrowserMediaCandidate` and `BrowserMediaController` (tab scan / select /
    volume via injected JS). `WorkspacePresenceChecker.swift`,
    `PermissionsManager.swift`, `LoginItem.swift` (SMAppService),
    `AudioProcessMonitor.swift` (Core Audio "recently playing" list, macOS 14.2+),
    `WorkspaceAppLauncher.swift` (launch target apps on media-key press).
    `UpdaterModel.swift` — all Sparkle code sits behind `#if OFFICIAL_BUILD`.
  - `UI/MenuContentView.swift`, `SettingsWindow.swift`, `SettingsView.swift`,
    `AgentWindowPresenter.swift`, `AddAppView.swift`.

Flow of a key press: media key → `MediaKeyTap` (swallows the CGEvent) →
`AppState.handleKey` (on main) → `TargetManager.route(key)` → runs
`ScriptedMediaApp.perform` on the off-main **`ScriptRunner`** serial queue →
AppleScript to the target app. All AppleScript (`NSAppleScript`) runs on a
`ScriptRunner` off the main thread — never on main — bounded by a `with timeout`
in `AppleScriptExecutor`, so a slow/launching target can't freeze the UI or the
event tap. Volume-key repeats are coalesced in `AppState` (single-flight); the
1.5s play-state poll uses a separate read runner so it can't block key commands.

## Working on built-in apps (the common change)

Built-ins live in `BuiltInApps.swift` as `AppDefinition`s and are added to
`BuiltInApps.all`. When adding one:

- **It must be a native app with a real AppleScript dictionary.** Verify the exact
  commands (`sdef /Applications/Foo.app`, or a Scripting Bridge header) — do not
  guess. Electron/web apps (Amazon Music, TIDAL, Deezer, Plexamp) have none.
- **Coerce enum results to text.** `NSAppleScript`'s `.stringValue` is `nil` for
  enumeration constants, so a play-state script must end in `as text`
  (e.g. `return (player state as text)`), else `isPlaying()` always returns nil.
- Volume set scripts use the literal token `{volume}`; pick the right
  `volumeScaleKind` (`.integer(max:)` / `.unitFloat` / `.none`).
- Give each a unique `id`; a test asserts uniqueness and `isBuiltIn`.

## Menu-driven apps (no AppleScript dictionary)

Apps that ship no scripting dictionary can be driven by pressing their own menu
items over the Accessibility API — `MenuControl` on `AppDefinition`,
`MenuDrivenMediaApp` in the kit, `AXMenuItemPresser` in the app target. No extra
permission: the media-key tap already requires Accessibility. Volume is not
supported (menus only step it), so those targets report `supportsVolume == false`.

**Verify each app, and be careful how you verify.** IINA 1.4.4 works: the press
toggles playback and the item title reports state. But the title can lag a press,
so an unchanged title is NOT evidence the press failed — an early round of testing
concluded exactly that and was wrong. Core Audio is no better as a check, since a
paused player keeps its output stream open for a while (see the comment on
`AudioProcessMonitor`). The reliable signal is the title read a moment later, or
your own ears. Also confirm the app has something loaded: TIDAL's Play item with
an empty queue does nothing, which looks identical to a broken definition.

To map or validate an app, use `MenuProbe` — it dumps the whole menu bar and then
presses play/pause and re-reads the title:

```bash
defaults write com.github.ppixu.beamhook BHProbeBundleID com.example.player
./run.sh                       # output lands in /tmp/beamhook-menuprobe.txt
defaults delete com.github.ppixu.beamhook BHProbeBundleID
```

Note the dev build gets its **own** Accessibility entry — the grant on an
installed copy does not carry over, even signed with the same identity.

Write `menuIndex`/`itemIndex` only for positions actually observed; leave them nil
and list titles (`MenuItemPath.search`) when the layout is unmapped, so a
definition never asserts a position nobody checked. Observed so far: IINA and
TIDAL both put playback under menu 4; Amazon Music's indices come from
BeardedSpice; Plexamp and Deezer are unmapped and search by title.

## UI gotcha

`MenuBarExtra(.window)` popovers **dismiss when a `.sheet` takes focus** — so
anything bigger than a popover row opens in a real `NSWindow` instead
(`SettingsWindow`, `AddAppWindow`), never a sheet. Beamhook is an agent app, so
those windows go through `AgentWindowPresenter`, which flips the activation
policy to `.regular` while any of them is open and back to `.accessory` only
when the last one closes.

## Icons & landing page

- App/menu-bar icons are generated by `Icon/make-icons.sh` from
  `Icon/master-1024.png` (app tile) and `Icon/menubar-master.png` (monochrome
  template). Edit the masters, run the script, `xcodegen generate`, rebuild.
- `docs/index.html` is the GitHub Pages landing page (served from `main` `/docs`).
  Keep it **dependency-free**: inline CSS, the favicon embedded as a base64 data
  URI, and no requests off `docs/`. Its only `<img>` sources are the local
  `icon.png` and `hover-hint.png`; `docs/icon.png` / `docs/icon-dark.png` double
  as the README logos.
- `docs/appcast.xml` is **generated and EdDSA-signed** by
  `scripts/sign-release.sh`. Never hand-edit it — any change invalidates the
  signature and stops updates for every 1.1.1+ user.
